# MedGuard — ML Pipeline Design

**Dataset:** Triagegeist (synthetic)  
**Reproducibility:** all commands in §7; fixed seed `20260915`.  
**Status:** describes the current end-to-end system. The Phase-1-only MIMIC
design is preserved in the git history.

---

## 1. Purpose and scope

Build a reproducible, leakage-safe pipeline that turns the Triagegeist
synthetic release into a modelling frame for predicting the original
five-level ESI triage acuity from information available at initial triage, and
then trains, evaluates, explains and serves a research prototype model.

**Out of scope:** any clinical claim, any deployment for real triage, and any
use of real patient data.

## 4. Leakage prevention

### 4.1 Column-level

- Features come from the schema's explicit `role="feature"` set, not from a
  hand-maintained list.
- `ColumnTransformer(..., remainder='drop')` discards everything not allow-listed.
- `assert_no_leakage_columns` raises on any field the schema marks
  `role="leakage"` (`disposition`, `ed_los_hours`).
- `leakage_free_feature_names` raises if an identifier name reaches the model
  input matrix.
- Excluded: `disposition`, `ed_los_hours`, and the identifiers `patient_id`,
  `site_id`, `triage_nurse_id`.

### 4.2 Split-level

- `patient_id` is the grouping variable. `GroupShuffleSplit` and
  `GroupKFold` are used so a patient's encounters all land on one side.
- `assert_no_patient_overlap` raises `PatientOverlapError` on any shared
  patient.
- The released `train.csv` and `test.csv` share no patient; the within-cohort
  split is additionally asserted to have 0 overlap.

### 4.3 Fit-isolation level

- Imputation medians, one-hot categories and scaler statistics are all fitted
  *inside* the pipeline.
- Nothing is fitted on the full cohort before splitting.
- `tests/test_features.py` asserts that changing the training subset changes
  the imputed value for a missing entry, proving the statistic comes from the
  fitted data.
- The CV factory builds a **fresh** preprocessor per fold
  (`build_preprocessor_for_frame`), so no fold's statistics leak into another.

## 5. Data-splitting strategy

### 5.1 Hold-out split

| | Rows | Patients |
|---|---|---|
| Train | 64,000 | 64,000 |
| Holdout | 16,000 | 16,000 |
| **Total** | **80,000** | **80,000** |

- Splitter: `GroupShuffleSplit(test_size=0.2, random_state=20260915)` on
  `patient_id`.
- Triagegeist has one encounter per patient, so the row ratio and the patient
  ratio coincide exactly.

### 5.2 Cross-validation folds

5-fold patient-grouped CV over the 64,000 training rows, with a fresh
preprocessor per fold. Reported as mean ± std over the folds.

### 5.3 Stratified group splitting — feasible and used

`StratifiedGroupKFold` **is** usable for this cohort. `report_stratification_feasibility`
confirms that every ESI level is present and that every level has at least
`n_splits` members, so stratified grouped splitting is available for the
evaluation.

The recorded principle still holds:

> **The original five-level ESI labels are never collapsed or merged to make
> stratification easier.** Class imbalance is handled through **metric choice**
> (macro-F1, per-class recall, quadratic-weighted kappa) and through
> **disclosure** of per-class support, not through label surgery.

`report_stratification_feasibility` refuses to report a cohort as feasible
when a level is entirely absent or has fewer members than there are folds, and
`stratified_grouped_kfold` raises `SplitError` rather than silently producing
empty folds.

## 6. Preprocessing specification

```
ColumnTransformer([
    ('numeric',    Pipeline([('imputer', SimpleImputer(median)),
                             ('scaler',  StandardScaler())]),
                   [age, arrival_hour, ..., num_comorbidities]),
    ('categorical', Pipeline([('imputer', SimpleImputer(most_frequent)),
                              ('onehot',  OneHotEncoder(handle_unknown='ignore',
                                                       drop='first',
                                                       sparse_output=False))]),
                   [sex, language, insurance_type, arrival_mode,
                    transport_origin, arrival_season, shift,
                    chief_complaint_system]),
    ('boolean',    Pipeline([('cast',    FunctionTransformer(cast_boolean_to_float)),
                             ('imputer', SimpleImputer(most_frequent))]),
                   [hx_* flags]),
], remainder='drop', verbose_feature_names_out=False)
```

Design rationale:

| Decision | Reason |
|---|---|
| Median imputation | Robust to the rejected outliers; a mean would be dragged by them |
| Missingness indicators | An unobtainable pain score or absent vitals correlates with acuity; discarding that signal would lose information |
| `handle_unknown='ignore'` | An unseen category at inference degrades gracefully instead of crashing |
| Boolean → float cast | `SimpleImputer` rejects a bool dtype; Triagegeist ships the flags as 0/1 integers but a boolean frame is equally valid |
| `StandardScaler` | Harmless for tree models, required for linear baselines |
| `remainder='drop'` | Any column not allow-listed is physically removed from the model input |
| Column list intersected with the frame | The comorbidity history is not joined for the served model; requesting an absent column would make the transformer fail at fit time |

## 7. Reproduction commands

Run from the project root `/secondary/MedGuard`.

### 7.1 Create the environment (one time)

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

### 7.2 Run the pipelines

```bash
# Data quality report (docs/DATA_QUALITY_REPORT.md + reports/data_preparation_report.json)
venv/bin/python -m backend.ml.run_data_prep

# Train, select and persist the model artifact
venv/bin/python -m backend.ml.triagegeist_training

# Regenerate every aggregate report artifact
venv/bin/python -m backend.ml.build_reports
```

### 7.3 Run the test suite

```bash
venv/bin/python -m pytest tests/ -v
cd frontend && npx vitest run
```

### 7.4 Check that no dataset is staged in Git

```bash
git check-ignore -v triagegeist/train.csv
```

Expected: `triagegeist/` is ignored, so no dataset file appears as untracked
or staged.

## 8. Random seed and determinism

- A single seed (`20260915`) drives the split, the model `random_state` and
  the cross-validation shuffle.
- Two runs with the same seed produce identical splits and identical
  predictions (asserted by `tests/test_splitting.py` and
  `tests/test_model_pipeline.py`).
- The manifest records the seed, the library versions and the training class
  distribution, so a run can be compared against the artifact it produced.

## 9. Known limitations

1. **Synthetic data only.** Every metric is measured on synthetic records.
2. **The holdout numbers describe the evaluation-time model.** The deployed
   artifact is refitted on all 80,000 labelled rows after selection.
3. **The comorbidity history is not served.** The API cannot supply it, so the
   model does not use it — see `docs/FEATURE_SPECIFICATION.md` §2.3.
4. **`test.csv` ground truth is withheld**, so no metric can be reported for
   the competition test set.
5. **Not clinically validated.** The prototype must not be used for triage
   decisions.
