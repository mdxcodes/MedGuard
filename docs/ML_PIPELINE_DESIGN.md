# MedGuard — ML Pipeline Design

**Phase:** 1 (data preparation) — no model is trained or selected in this phase.
**Reproducibility:** all commands in §7; fixed seed `20260915`.

---

## 1. Purpose and scope

Build a reproducible, leakage-safe data-preparation pipeline that turns the
licensed MIMIC-IV-ED demo dataset into a modelling frame for predicting the
original five-level ESI triage acuity from information available at initial
triage.

**Out of scope for this phase:** model training, model selection, evaluation
metrics, any performance claim, any clinical claim, frontend/backend/database
work, and deployment.

## 3. Pipeline stages

```
                    +---------------------------+
  ZIP / gz CSVs --> | 1. Checksum verification  |  sha256 vs SHA256SUMS.txt
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 2. Schema validation      |  required cols + dtypes
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 3. One-to-one join        |  triage <-> edstays on stay_id
                    |    (triage + edstays)    |  duplicate/orphan guards
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 4. Quality rules          |  temperature, BP, pain,
                    |    (deterministic)       |  complaint, target filter
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 5. Drop unlabelled rows   |  15 rows, never imputed
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 6. Patient-grouped split  |  subject_id, seed 20260915
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 7. Fit preprocessor       |  TRAIN ROWS ONLY
                    |    (ColumnTransformer)   |  no full-data statistics
                    +---------------------------+
                                 |
                    +---------------------------+
                    | 8. Reports                |  JSON + Markdown
                    +---------------------------+
```

Stages 4 is deterministic (no fitted statistics), so it is safe to apply before
splitting. Stage 7 is the only fitting step, and it is applied to training rows
only.

## 4. Leakage prevention

### 4.1 Column-level

- Features come from an explicit allow-list in `config.py`.
- `ColumnTransformer(..., remainder='drop')` discards everything not allow-listed.
- `assert_no_leakage_columns` raises on any `FORBIDDEN_FEATURE_COLUMNS` member
  (tolerating only `subject_id`, `stay_id`, and the target, which the pipeline
  drops before the estimator).
- `leakage_free_feature_names` raises if an identifier name reaches the model
  input matrix.
- Excluded: `disposition`, `outtime`, `hadm_id`, `diagnosis`, `pyxis`,
  `medrecon`, all of `vitalsign`, `race`, `gender`, `intime`.

### 4.2 Split-level

- `subject_id` is the grouping variable. `GroupShuffleSplit` and `GroupKFold`
  are used so a patient's multiple visits all land on one side.
- `assert_no_patient_overlap` raises on any shared patient.
- Verified on the real cohort: 44 train patients + 12 test patients = 56,
  with **0 overlap**.

### 4.3 Fit-isolation level

- Imputation medians, one-hot categories, `min_frequency` groupings and the
  TF-IDF vocabulary are all fitted *inside* the pipeline.
- Nothing is fitted on the full cohort before splitting.
- `tests/test_features.py::test_tfidf_vocabulary_comes_from_train_only`
  injects a train-only and a test-only token and asserts the test-only token
  never enters the vocabulary.
- A test also confirms that changing the training subset changes the imputed
  value for a missing entry, proving the statistic comes from the fitted data.

## 5. Data-splitting strategy

### 5.1 Hold-out split

| | Rows | Patients |
|---|---|---|
| Train | 163 | 44 |
| Test | 44 | 12 |
| **Total** | **207** | **56** |

- Splitter: `GroupShuffleSplit(test_size=0.2, random_state=20260915)` on
  `subject_id`.
- Note the split is on **patients**, not rows, so the row ratio differs from
  80/20: one patient contributes 23 of 207 rows, and that patient lands
  entirely on one side.

### 5.2 Cross-validation folds

`GroupKFold(n_splits=5)` on `subject_id`:

| Fold | Train rows | Train patients | Val rows | Val patients |
|---|---|---|---|---|
| 0 | 165 | 45 | 42 | 11 |
| 1 | 165 | 44 | 42 | 12 |
| 2 | 166 | 45 | 41 | 11 |
| 3 | 166 | 45 | 41 | 11 |
| 4 | 166 | 45 | 41 | 11 |

Only fold 3 contains the two ESI Level 4 rows, so per-class metrics for
Level 4 are computable in that fold alone.

### 5.3 Stratified group splitting — investigated, not used

`StratifiedGroupKFold` was evaluated and **found infeasible** for this cohort,
verified by `report_stratification_feasibility`:

- **ESI Level 5 has zero rows** — no stratification can place an absent class
  in every fold.
- **ESI Level 4 has 2 rows** — fewer than `n_splits=5`.

Attempting it raises from scikit-learn. The recorded conclusion:

> **The original five-level ESI labels are never collapsed or merged to make
> stratification easier.** `GroupKFold` (unstratified) is used for model
> selection. Class imbalance is handled through **metric choice** (macro-F1,
  per-class recall, quadratic-weighted kappa) and through **disclosure** of
  per-fold class support, not through label surgery.

` StratifiedGroupKFold` remains available and is tested to work on a balanced
five-label synthetic frame, so it will be adopted automatically once the full
dataset supplies adequate Level 4 and Level 5 support.

## 6. Preprocessing specification

```
Pipeline([
  ('derive', FunctionTransformer(derive_features, validate=False)),
  ('encode', ColumnTransformer([
      ('num',     Pipeline([('impute', SimpleImputer(median)),
                            ('scale', StandardScaler())]),
                 [temperature, heartrate, resprate, o2sat, sbp, dbp]),
      ('derived', Pipeline([('impute', SimpleImputer(median)),
                            ('scale', StandardScaler())]),
                 [shock_index, pulse_pressure, abnormal_vital_count]),
      ('cat',     Pipeline([('impute', SimpleImputer(constant, 'missing')),
                            ('onehot', OneHotEncoder(handle_unknown='ignore',
                                                     min_frequency=5,
                                                     sparse_output=False))]),
                 [arrival_transport]),
      ('text',    Pipeline([('fill', TextBlockFlattener()),
                            ('tfidf', TfidfVectorizer(min_df=5,
                                                      max_features=300,
                                                      sublinear_tf=True,
                                                      token_pattern=
                                                      r'[A-Za-z][A-Za-z0-9/]+'))]),
                 [chiefcomplaint]),
      ('flags',   'passthrough',
                 [temperature_missing, ..., pain_missing]),
  ], remainder='drop', verbose_feature_names_out=False))
])
```

Design rationale:

| Decision | Reason |
|---|---|
| Median imputation | Robust to the rejected 879 mmHg-style outliers; a mean would be dragged by them |
| Missingness indicators | An unobtainable pain score or absent vitals correlates with high acuity; discarding that signal would lose information |
| `min_frequency=5` in one-hot | Groups rare categories so small folds do not create sparse indicator columns |
| `handle_unknown='ignore'` | An unseen arrival-transport value in a later fold degrades gracefully instead of crashing |
| `min_df=5`, `max_features=300` in TF-IDF | 207 rows with 168 distinct complaints would otherwise memorise the text vocabulary |
| Tokens of >= 2 characters | Excludes single-letter `L`/`R` noise |
| `StandardScaler` | Harmless for tree models, required for linear/SVM baselines |
| `remainder='drop'` | Any column not allow-listed is physically removed from the model input |
| Derived features inside the pipeline | Keeps the fitted object self-contained and picklable, with nothing pre-computed on the full cohort |

## 7. Reproduction commands

Run from the project root `/secondary/MedGuard`.

### 7.1 Create the environment (one time)

```bash
python3 -m venv venv
venv/bin/pip install -r requirements.txt
```

Verified on Python 3.14.7 / CachyOS Linux. `pip` on this distribution is
externally managed (PEP 668), so the virtual environment is required; system
Python was not modified.

### 7.2 Run the data-preparation pipeline

```bash
venv/bin/python -m backend.ml.run_data_prep
```

Options:

```bash
venv/bin/python -m backend.ml.run_data_prep --seed 20260915 --verbose
venv/bin/python -m backend.ml.run_data_prep \
    --output-json reports/data_quality_report.json \
    --output-markdown docs/DATA_QUALITY_REPORT.md
```

Writes:

- `reports/data_quality_report.json` (machine-readable, gitignored)
- `docs/DATA_QUALITY_REPORT.md` (human-readable)

### 7.3 Run the test suite

```bash
venv/bin/python -m pytest tests/ -v
```

All 111 tests are expected to pass. Synthetic fixtures are generated in
memory and in temporary directories; no research data is read into tests
except through checksum-verified loaders that assert invariants only.

### 7.4 Check that no research data is staged in Git

```bash
git status --short
git check-ignore -v mimic-iv-ed-demo-2.2/ed/triage.csv.gz
```

Expected: no `mimic-iv-ed*` path appears as untracked or staged, and the
second command reports the `.gitignore` rule that excludes it.

## 8. Random seed and determinism

- `RANDOM_SEED = 20260915`, defined in `backend/ml/config.py`.
- Used by `GroupShuffleSplit` and `StratifiedGroupKFold`.
- `splits_are_reproducible` confirms two identical seeded calls produce
  identical `stay_id` membership.
- `Pipeline` objects are picklable (tested via `pickle`; joblib in Phase 2).

## 9. Known limitations of this phase

1. Demo subset only (222 stays, 64 patients). Every number here is indicative.
2. ESI Level 5 absent, Level 4 near-absent; five-class evaluation is not
   possible for those levels on this subset.
3. No age feature (core `patients` table unavailable).
4. No data dictionary in the demo package; column semantics are inferred from
   the audited values and must be re-verified against the official dictionary.
5. No model has been trained, so no baseline or performance figure exists.
