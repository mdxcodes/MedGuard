
All tests pass. Four defects were found and fixed during test development:

1. `verify_checksums` orphan detection was masked by `min()` — now raises on
   either side of the join being asymmetric.
2. Chief-complaint placeholders were compared case-sensitively against an
   uppercased string, so `UNKNOWN-CC` was not recognised — now case-insensitive.
3. The leakage guard wrongly flagged the target column and `stay_id` — now
   tolerates the grouping/identifier columns that the pipeline itself drops.
4. A fixture typo (`np.arange(500000 + n)`) — corrected.

## 6. Confirmation: train/test split prevents patient overlap

Verified three independent ways:

1. **Runtime assertion.** `assert_no_patient_overlap` raises if any patient is
   shared. The pipeline invokes it on every run.
2. **Pipeline run.** `patient_overlap: 0` with 44 train patients + 12 test
   patients = 56 modelling patients.
3. **Test suite.** `tests/test_splitting.py` asserts the guard raises on a
   deliberately leaked split, that repeat patients stay entirely on one side,
   that folds partition all rows exactly once with no shared patient, and the
   end-to-end test asserts 0 overlap on the real cohort.

Split details:

- Splitter: `GroupShuffleSplit(test_size=0.2, random_state=20260915)` grouped
  on `subject_id`.
- Seed recorded in `backend/ml/config.py` (`RANDOM_SEED = 20260915`).
- `splits_are_reproducible` confirms identical `stay_id` membership on repeated
  seeded calls.
- Note the row ratio is 163/44 rather than 80/20 because grouping is on
  patients, and one patient contributes 23 of 207 rows.

### Stratified group splitting

Investigated and found **infeasible** on this subset: ESI Level 5 has 0 rows
and Level 4 has 2 rows, below `n_splits=5`. `StratifiedGroupKFold` therefore
cannot place every class in every fold. The original five labels were **not**
collapsed or merged to work around this; `GroupKFold` is used instead, with
imbalance handled through macro-F1, per-class recall, quadratic-weighted kappa
and explicit per-fold class-support disclosure. A test confirms stratified
splitting works once all five levels have adequate support.

## 7. Remaining blockers and recommendations for Phase 2

### Blockers / gaps

| # | Blocker | Impact | Resolution |
|---|---|---|---|
| 1 | **No age feature.** The MIMIC-IV core `patients` table was not supplied | Age is a strong, standard triage predictor; the baseline model is missing it | Obtain credentialed access to MIMIC-IV core, derive age at visit, verify the `subject_id` join, then add it to the allow-list with tests |
| 2 | **No official data dictionary** in the demo package | Column semantics (especially `acuity`, pain sentinels, temperature units) are inferred from audited values rather than confirmed | Obtain the official MIMIC-IV-ED data dictionary and re-verify the rules; update `backend/ml/validation.py` if any inference was wrong |
| 3 | **Demo subset only** (222 stays / 64 patients) | No reliable generalisation or performance estimate is possible; class support is 0–2 for Levels 4–5 | Request access to the full MIMIC-IV-ED release (~425k stays) and re-run the identical pipeline on it |
| 4 | **ESI 5 absent, ESI 4 sparse** | Five-class classification cannot be evaluated for those levels; stratification is infeasible | On the full dataset, re-run `report_stratification_feasibility`; adopt `StratifiedGroupKFold` automatically once support is adequate |

### Recommendations for Phase 2 (model training and evaluation)

1. **Establish baselines before any model.** Add `DummyClassifier`
   (`stratified` and `prior`) and a simple interpretable baseline (single
   vital threshold or small decision tree) so every model has something to
   beat. No performance claim should be made before these exist.
2. **Use `GroupKFold(5)` on `subject_id`** for model selection, with the entire
   `Pipeline` (not pre-transformed arrays) inside the fold so all preprocessing
   is refitted per fold.
3. **Report metrics honestly:** per-class precision/recall/F1, macro-F1,
   quadratic-weighted kappa (appropriate for ordinal ESI labels), the confusion
   matrix, and fold means with standard deviations. Label Levels 4 and 5 as
   "insufficient support — not evaluated" on the demo subset.
4. **Keep the five-level target** and the `1–5` encoding so retraining on the
   full dataset requires no schema change.
5. **Add a leakage regression test** that fails the suite if any excluded
   column name is added to the allow-list.
6. **Re-run the pipeline on the full dataset before any claim**, and re-check
   the temperature unit distribution and pain sentinel set on the full data —
   both rules are data-driven and may behave differently at scale.
7. **Delay any clinical framing** until a model exists, is evaluated on the
   full dataset with proper patient-grouped splits, and has been reviewed by a
   clinician. Nothing in this phase is or should be described as clinically
   validated.
